## 0. 项目背景

项目名称：FITNESS OS 2.0

当前阶段：PHASE 1.1 已完成。

现在正式启动：PHASE 2。

PHASE 2 核心目标：

将当前视觉原型升级为具有真实用户体系、云端数据库、私人数据隔离和多设备同步能力的在线 Web App。

开发环境：Codex Cloud。

技术基础：Next.js + React + TypeScript。

数据库：Supabase PostgreSQL。

项目必须保持低成本，优先使用免费套餐，不购买不必要的服务。

## 3. 数据库基础结构

建立标准化数据库迁移。

至少包含：

### profiles
用户基本资料。

字段建议：
- id
- username
- avatar_url
- display_name
- created_at
- updated_at

关联 Supabase auth.users。

### user_preferences
用户个人设置。

字段建议：
- id
- user_id
- theme
- language
- unit_system
- timezone
- notification_preferences
- created_at
- updated_at

### user_consents
用户授权及隐私同意记录。

### sync_metadata
记录设备同步状态、版本及同步时间。

### user_data_exports
用户数据导出任务及状态。

以上表结构应根据实际需要调整，避免冗余。

同时编写未来业务数据的数据库设计文档，遵循已经确定的运动、游泳、营养、设备和AI模块架构。

不要在本阶段为了追求表数量而创建大量没有实际用途的空表。

所有用户数据表必须具备清晰的用户归属。

## 4. 用户注册与登录

实现完整用户体系。

至少包括：

1. 邮箱注册。
2. 邮箱验证。
3. 邮箱登录。
4. 退出登录。
5. 忘记密码。
6. 重置密码。
7. 登录状态持久化。
8. 会话过期处理。
9. 未登录访问控制。
10. 用户资料修改。

要求：

- 使用 Supabase Auth。
- 不将密码存入自建数据库。
- 不在前端保存管理员密钥。
- 不允许不同用户共享私人数据。
- 登录界面延续 FITNESS OS 的高级视觉设计。
- 桌面与移动端都要适配。

优先使用成本较低的邮箱认证方式。

暂时不接入短信验证码和收费第三方 OAuth。

## 5. RLS 数据权限

这是本阶段最重要的安全任务之一。

所有私人数据必须启用 Row Level Security。

必须验证：

用户A只能读取和修改用户A的数据。

用户B只能读取和修改用户B的数据。

匿名用户不能访问私人数据。

普通用户不能通过修改请求参数读取其他人的数据。

必须测试：

- SELECT
- INSERT
- UPDATE
- DELETE
- Storage文件访问
- 用户退出后的访问
- Token过期后的访问
- 跨用户越权访问

所有权限必须通过真实数据库测试。

不能只在前端隐藏按钮来代替权限控制。

service_role或secret key只能保存在服务端环境中。

## 6. 手机与电脑云端同步

实现同一账号的多设备同步基础。

使用：

- Supabase PostgreSQL
- Supabase Realtime（确有需要时）
- IndexedDB
- Offline Queue
- Sync Engine

要求：

1. 手机登录后可以读取电脑上保存的数据。
2. 电脑登录后可以读取手机上保存的数据。
3. 修改资料后可以同步。
4. 网络断开时保留待同步操作。
5. 网络恢复后自动尝试同步。
6. 重复请求不能产生重复记录。
7. 同步失败要显示明确原因。
8. 不允许静默丢失用户数据。

设计幂等键、重试机制和冲突处理。

对于同一记录的并发修改：
- 使用版本号或更新时间检测冲突。
- 不得无条件覆盖较新的用户数据。
- 对无法自动合并的冲突保留用户选择能力。

必须实现并测试真实的跨设备数据同步，不允许只做一个视觉演示。

## 7. Storage 文件存储

为未来食品图片、训练图片、运动记录附件及个人媒体做好基础。

建立私有文件存储策略。

要求：

- 用户只能访问自己的私人文件。
- 上传文件需要类型验证。
- 设置文件大小限制。
- 防止不安全文件上传。
- 使用受控访问或签名URL。
- 文件删除时处理关联记录。
- 不允许私人图片被公开访问。

公开的品牌图片继续使用项目 public 目录，不要重复上传到私人 Storage。

## 8. 离线与PWA

保留现有 PWA。

进一步完善：

- 登录状态管理。
- 离线状态提示。
- 网络恢复提示。
- 待同步任务状态。
- 同步失败重试。
- 退出登录时清理用户私有缓存。
- 切换账户时隔离本地数据。

特别注意：

不要将私人健康数据、心率、睡眠、GPS轨迹、身体指标等放入公共 Service Worker 缓存。

不得为了实现离线而牺牲用户隐私。

## 9. 用户数据管理

包括：

1. 查看个人资料。
2. 修改个人资料。
3. 查看账号信息。
4. 导出个人数据。
5. 删除个人账号。
6. 删除账号前二次确认。
7. 删除关联私人文件。

账号删除必须处理 Auth 用户、数据库数据和私人文件之间的关联，避免残留。

- CSRF及认证回调安全。

- API速率限制。
- 输入校验。

## 12. 测试要求

必须进行：

### 单元测试
数据库操作、数据校验、同步逻辑、权限判断。

### 集成测试
注册、登录、资料保存、数据读取、数据更新。

### 安全测试
至少创建两个独立测试用户，进行跨用户越权测试。

### 浏览器测试
桌面端、手机端、深色模式、浅色模式。

### 同步测试
两种不同浏览器或设备会话，验证数据同步。

### 离线测试
断网、写入、恢复网络、同步成功、重复提交。

### 回归测试
PHASE 1.1原有测试必须全部继续通过。

不能通过删除测试或降低断言来获得通过结果。
