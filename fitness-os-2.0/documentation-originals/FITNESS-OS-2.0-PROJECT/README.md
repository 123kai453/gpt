# FITNESS OS 2.0 — 项目文档包

本包是完整产品需求、技术架构、数据库基线、Codex开发指令、测试和部署文档，不是已完成的网站源代码。

## 使用顺序
1. 将整个目录放入 Codex 工作区，建议放在项目根目录的 `docs/`。
2. 先阅读 `03-Codex开发指令/MASTER_PROMPT.txt`。
3. Codex 必须先执行 PHASE 0 环境检查和技术可行性报告，不得直接生成全部业务代码。
4. 用户确认后，按 `PHASES.md` 分阶段开发。
5. 每次变更更新对应文档、`CHANGELOG.md`、功能状态和测试结果。

## 本版本新增
- 多张食品包装照片合并识别配料表、营养成分表、商品信息。
- 运动中心：游泳、户外跑步、跑步机爬坡、室内动感单车、徒步/登山、椭圆机、划船机、跳绳、登山机及可扩展运动。
- GPS路线记录与手动记录双模式。
- 训练计划、饮食计划、运动记录支持长文本导入；另预留截图/图片/文档解析。
- Apple Watch/Apple Health、华为手表/Huawei Health生态连接架构；实际设备同步后续实施，必须先核实平台权限和SDK要求。
- 用户可自主制定、编辑、复制、版本化训练计划。

## 重要限制
- Apple HealthKit 不能由普通网页/PWA直接调用；通常需要原生 iOS 容器/伴侣应用获取用户授权后同步到云端。
- 华为数据接入必须按具体产品、系统、地区、SDK和开发者权限核实；不能假定所有华为设备数据都能无条件读取。
- 浏览器GPS在前台且用户授权时可用；后台持续定位、锁屏记录和可靠运动追踪在iOS PWA等环境存在限制。需要可靠后台追踪时，应规划原生伴侣应用。
- 初期不购买设备SDK、域名或AI额度；先完成数据模型、适配器接口、手动/文件导入和模拟器测试。正式接入前核实官方资质与费用。
- `.env.example` 不含真实密钥。真实 `.env.local` 不得提交Git或发送到聊天中。
- 历史训练数据必须标注历史日期/来源/待确认状态，不得当作当前实时指标。
